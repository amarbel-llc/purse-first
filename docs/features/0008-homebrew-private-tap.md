# FDR: Homebrew Private Tap Distribution

**Status:** Prototype validated, awaiting polish
**Date:** 2026-03-12

## Summary

`purse-first package brew` can generate a complete Homebrew tap from a
`brew-config.json`, including formulas, tarballs, a download strategy for
private repos, and a marketplace.json. The end-user experience is:

```bash
brew tap org/tap git@github.com:org/tap.git
brew install org/tap/meta-formula
```

This installs binaries, registers a Claude Code plugin marketplace, and
installs all packages.

## Architecture

A consumer repo (the "tap repo") contains only generated artifacts:

```
tap-repo/
  Formula/
    grit.rb                           # per-package formula
    tote.rb                           # meta-formula (marketplace + deps)
  lib/
    custom_download_strategy.rb       # auth for private repo downloads
  tarballs/
    grit-0.1.0-darwin-arm64.tar.gz
    tote-0.1.0.tar.gz
  brew-config.json                    # input config
```

Everything is generated by:

```bash
purse-first package brew --config brew-config.json --output .
```

### Config

```json
{
  "name": "tote",
  "description": "Etsy engineering tools",
  "owner": {"name": "etsy", "email": "engineering@etsy.com"},
  "releaseRepo": "sfriedenberg-etsy/tote",
  "tapName": "sfriedenberg-etsy/tote",
  "license": "MIT",
  "private": true,
  "packages": {
    "grit": {
      "description": "Git operations via MCP",
      "version": "0.1.0",
      "binary": true,
      "homepage": "https://github.com/amarbel-llc/purse-first",
      "category": "development",
      "tags": ["git", "mcp"],
      "platforms": {
        "darwin-arm64": "/path/to/built/bin/grit"
      },
      "share": "/path/to/built/share/purse-first/grit",
      "brewDeps": []
    }
  }
}
```

Setting `"private": true` triggers generation of the download strategy and
`require_relative`/`using:` directives in all formulas.

### Generated formulas

**Per-package formula** (e.g. `grit.rb`):

```ruby
require_relative "../lib/custom_download_strategy"

class Grit < Formula
  desc "Git operations via MCP"
  homepage "https://github.com/amarbel-llc/purse-first"
  version "0.1.0"
  license "MIT"

  on_macos do
    if Hardware::CPU.arm?
      url "https://github.com/org/tap/releases/download/v0.1.0/grit-0.1.0-darwin-arm64.tar.gz",
          using: GitHubPrivateRepositoryReleaseDownloadStrategy
      sha256 "..."
    end
  end

  def install
    bin.install "bin/grit"
    (share/"purse-first/grit").install Dir["share/purse-first/grit/*"]
  end

  test do
    system bin/"grit", "--help"
  end
end
```

**Meta-formula** (e.g. `tote.rb`):

```ruby
require_relative "../lib/custom_download_strategy"

class Tote < Formula
  desc "Etsy engineering tools"
  homepage "https://github.com/org/tap"
  version "0.1.0"
  license "MIT"
  url "https://github.com/org/tap/releases/download/v0.1.0/tote-0.1.0.tar.gz",
      using: GitHubPrivateRepositoryReleaseDownloadStrategy
  sha256 "..."

  depends_on "grit"

  def install
    (share/"purse-first").install "marketplace.json"
    (prefix/".claude-plugin").install share/"purse-first/marketplace.json"
  end

  def post_install
    system "purse-first", "install", prefix
  end

  test do
    assert_predicate prefix/".claude-plugin/marketplace.json", :exist?
  end
end
```

### `purse-first install [marketplace-root]`

The `install` command accepts an optional positional argument specifying the
marketplace root directory. When provided, it uses that path directly instead
of resolving from the executable location. The meta-formula passes `prefix`
(e.g. `/opt/homebrew/Cellar/tote/0.1.0`) so the correct marketplace is
registered.

Without the argument, resolution falls back to:
1. `PURSE_FIRST_PLUGINS_DIR` env var (two levels up)
2. Executable symlink resolution (two levels up from resolved binary)

## Homebrew Constraints and Workarounds

These are hard-won lessons from the prototype. Each represents a constraint
that the implementation must respect.

### Private repo downloads require a custom strategy

Homebrew cannot download release assets from private GitHub repos natively.
The `GitHubPrivateRepositoryReleaseDownloadStrategy` handles this by:

1. Authenticating via `GitHub::API.credentials`
2. Resolving the release asset ID via the GitHub REST API
3. Getting a pre-signed redirect URL for the actual binary download

**Critical implementation details:**

| Do                                     | Don't                                           |
|----------------------------------------|--------------------------------------------------|
| `GitHub::API.credentials` for tokens   | `ENV["GH_TOKEN"]` (stripped by Homebrew)          |
| Plain `Net::HTTP` + `JSON` for API     | `GitHub::API.open_rest` (throws removed errors)   |
| `require_relative "../lib/..."` in rb  | `require` with absolute/gem paths                 |
| `CurlDownloadStrategyError` for errors | `GitHub::HTTPNotFoundError` (doesn't exist)       |

Homebrew sanitizes the environment during formula execution, stripping all
non-`HOMEBREW_*` env vars. `GitHub::API.credentials` is the only reliable
token source — it checks `HOMEBREW_GITHUB_API_TOKEN`, the `gh` CLI auth
store, and the macOS keychain.

### Tarball structure

- **Binary paths are preserved.** If the tarball contains `bin/grit`, the
  formula must use `bin.install "bin/grit"`, not `bin.install "grit"`.

- **Single top-level directories are stripped.** If a tarball contains only
  `subdir/file.json`, Homebrew extracts it as `file.json` (stripping
  `subdir/`). Put files at the tarball root to avoid surprises.

- **Dotfile-only archives are rejected.** A tarball containing only
  `.claude-plugin/marketplace.json` triggers `RuntimeError: Empty archive`.
  At least one non-dotfile entry must exist.

### Installation visibility

- **Dotfile-only installs are rejected.** Installing only to
  `prefix/.claude-plugin/` triggers `Error: Empty installation`. Homebrew
  requires at least one visible (non-dot) file.

- **Workaround:** Install to a visible path first, then copy to the dotfile
  location:

  ```ruby
  (share/"purse-first").install "marketplace.json"
  (prefix/".claude-plugin").install share/"purse-first/marketplace.json"
  ```

### `post_install` runs the system binary

`system "purse-first", "install", prefix` calls whatever `purse-first` is in
Homebrew's PATH during `post_install`. During development, this is often an
older version that doesn't support the positional arg. The dev justfile works
around this with `brew install ... || true` followed by a direct call to the
dev binary.

In production, `purse-first` must be installed (via brew or nix) with the
`install [marketplace-root]` support before the tap can be used.

## Validation

### Unit tests

```
go test ./internal/packagebrew/... — PASS
```

  formula output

### End-to-end validation

Full cycle tested via `just dev 0.1.0` in the tote tap repo:

1. **Build purse-first** from local worktree source (`nix shell nixpkgs#go`)
2. **Build grit** from nix flake
3. **Generate** config, formulas, tarballs, download strategy
4. **Create GitHub release** with tarballs on private repo
5. **`brew tap`** the private repo via SSH
6. **`brew install`** the meta-formula

**Verified outcomes:**

- Private repo download strategy authenticates and downloads release assets
  (grit binary tarball + tote marketplace tarball)
- grit binary installs to `/opt/homebrew/bin/grit` and runs (`grit --help`)
- grit share data installs to
  `/opt/homebrew/share/purse-first/grit/` (mappings.json, hooks)
- tote marketplace.json installs to both
  `/opt/homebrew/share/purse-first/marketplace.json` (visible) and
  `/opt/homebrew/Cellar/tote/0.1.0/.claude-plugin/marketplace.json`
- `purse-first install <prefix>` reads tote marketplace (1 package),
  registers with Claude Code, installs grit plugin — all TAP steps pass:

  ```
  TAP version 14
  1..5
  ok 1 - resolve marketplace root
  ok 2 - read marketplace.json (1 packages)
  ok 3 - remove marketplace  tote
  ok 4 - add marketplace  tote
  ok 5 - install package  grit
  ```

### Iterative issues resolved during validation

| # | Error | Root cause | Fix |
|---|-------|-----------|-----|
| 1 | `GitHub::HTTPNotFoundError` uninitialized | Removed API in modern Homebrew | Removed `validate_github_repository_access!` entirely |
| 2 | `GitHub::API::HTTPNotFoundError` | `GitHub::API.open_rest` uses removed error class | Replaced with plain `Net::HTTP` |
| 3 | 404 from release metadata API | Token from wrong source | Switched to `GitHub::API.credentials` |
| 4 | `Errno::ENOENT: grit` | Tarball has `bin/grit`, formula expected `grit` | Changed to `bin.install "bin/grit"` |
| 5 | `RuntimeError: Empty archive` | Dotfile-only tarball (`.claude-plugin/`) | Changed to non-dot path, then root-level |
| 6 | `Errno::ENOENT: claude-plugin/marketplace.json` | Homebrew strips single top-level dir | Put `marketplace.json` at tarball root |
| 7 | `Error: Empty installation` | Dotfile-only install dir | Dual-install: `share/` then `.claude-plugin/` |
| 8 | `post_install` installs wrong marketplace | `purse-first install` resolved from exe, found nix marketplace | Added `[marketplace-root]` positional arg, formula passes `prefix` |
