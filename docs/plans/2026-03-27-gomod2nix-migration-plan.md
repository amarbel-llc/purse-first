# Migrate purse-first Go build from buildGoModule to gomod2nix

**Status:** accepted (executed 2026-04-08)

## Problem

The original build used `buildGoModule` with a manually-managed `goVendorHash`.
Adding/removing external Go deps required running `just vendor-hash` to recompute
the hash. The hash was opaque — a maintainer with a warm Nix store could land
stale-hash drift without noticing, and only downstream consumers on a clean
store would hit the resulting fixed-output mismatch (see purse-first#22).

## Decision

Migrate to `pkgs.buildGoApplication` from
[amarbel-llc/gomod2nix](https://github.com/amarbel-llc/gomod2nix), a fork of
`nix-community/gomod2nix` that adds native `go.work` support and a build cache
fix for large workspaces. The lockfile is `gomod2nix.toml`, checked in at the
workspace root, regenerated by `gomod2nix` (which detects `go.work` and merges
replace maps from each child `go.mod`).

The fork's go.work support originally had a bug where indirect deps with empty
`vendorPackages` were omitted from the synthetic `vendor/modules.txt`, causing
`go build -mod=vendor` to reject the tree. Reported and fixed in
[amarbel-llc/gomod2nix#1](https://github.com/amarbel-llc/gomod2nix/issues/1)
(commit `c721288`) before this migration landed.

## Changes (as executed)

1. **`flake.nix`** — `gomod2nix.url` points at `github:amarbel-llc/gomod2nix`.
   `goVendorHash` removed. `gomod2nix.toml` added to the `goWorkspaceSrc`
   filter. `purse-first-build` carries `goOverlays = [ gomod2nix.overlays.default ]`.
2. **`lib/mkMarketplace.nix`** — destructures `goOverlays` from
   `purse-first-build` and applies them when constructing the pkgs used for
   the Go build. No `goVendorHash` parameter anymore.
3. **`lib/mkGoWorkspaceModule.nix`** — switched to `pkgs.buildGoApplication`.
   Drops `vendorHash` and `overrideModAttrs`. Passes `pwd = goWorkspaceSrc`
   so the fork's parser finds `go.work`, and `modules = goWorkspaceSrc + "/gomod2nix.toml"`.
4. **`gomod2nix.toml`** — generated and checked in.
5. **`justfile`** — `build-nix-gomod2nix` recipe (`go work sync && gomod2nix`)
   is now a prerequisite of both `build` and `default`. `vendor`,
   `vendor-hash`, and `validate-vendor-hash` recipes removed. `deps` now
   aliases `build-nix-gomod2nix`.
6. **`.github/workflows/flakehub.yml`** — `build-nix-package` job runs
   `just build-nix-gomod2nix && git diff --exit-code -- gomod2nix.toml`
   before `nix build`. Drift in the checked-in lockfile fails CI explicitly
   instead of being masked by the in-store cache.
7. **`vendor/`** — directory removed; no longer needed.
8. **`CLAUDE.md`** — build commands and Go workspace section updated.

## Notes for future work

- The fork's `go.work` support is the only reason this migration is viable
  without `replace` directives in the root `go.mod`. If the fork's changes
  ever land upstream we can drop the fork pin and switch back to
  `github:nix-community/gomod2nix`.
- The CI drift check is the load-bearing guardrail for downstream consumers.
  If we ever stop running it, we'll re-introduce the same class of failure
  that issue #22 reported (just with `gomod2nix.toml` drift instead of
  `goVendorHash` drift).
